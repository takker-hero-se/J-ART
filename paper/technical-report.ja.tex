\begin{abstract}
大規模言語モデル（LLM）の公開レッドチーミング/ジェイルブレイク評価の多くは英語中心で、
かつ\emph{素のモデル}を対象とする。本稿は \textbf{J-ART}（日本語敵対的レッドチーム評価
フレームワーク）を提案する。J-ART は、(i) 素のモデルではなく
\textbf{アプリケーション構造層}——モデル $\times$ システムプロンプト強度 $\times$
ガードレール $\times$ 検索(RAG)——を評価し、(ii) ギャル文字による字形置換・縦書き/改行
分割・慇懃無礼（keigo）な権威付け・二枚舌の偽前提・Base64・leet/ゼロ幅密輸といった
\textbf{日本語特有の難読化変形}で素朴なキーワード検閲を突破し、(iii) 攻撃を
\textbf{MITRE ATLAS}（推論（運用）時に行われる9技術）に対応づけ、(iv) 防御率に \textbf{Wilson 95\%
信頼区間}を付し \textbf{コスト効率}指標を併記する、再現可能なオープンハーネスである。
攻撃は\emph{無害なプロキシ}（架空のカナリアと無害なマーカー）で構成され、\textbf{危険物を
一切含まず}、各攻撃の悪意あるコアは公開物上でマスクされる。21のアプリ構成と
11攻撃 $\times$ 7変形（防御率は実LIVE $K=5$ キャンペーン、差分の主張は3モデルの $K=3$ 均衡
アブレーション）にわたり、\textbf{アプリ層の構成が「素のモデル」の大きなばらつきを潰す}ことを
示す：素のモデルは防御29.6〜86.5\%とばらつくが、3モデルすべてで強化またはガードレール付きの
構成はいずれも\textbf{91〜100\%}帯に収まり、\textbf{一度アプリを構成するとモデル選択の差は
ほとんど効かなくなる}。\textbf{クラスタ頑健CI}のもとで\textbf{強化プロンプトとモデルベースの
ガードレールは各モデルで有意に防御を引き上げ}、軽量なkeyword/regexは素の弱いモデルほど効く
（天井付近では有意でなく、強化プロンプト側は飽和する）。防御率は\textbf{lexical-leak の上限}で
あり、真の拒否とマーカー抑制を完全には区別できない（第\ref{sec:limits}節）。単純な
\textbf{正規化フィルタ}が素朴なキーワードフィルタの取りこぼす難読化を無効化することを示す。さらに、構成を固定した$K=5$反復で
\textbf{9.6\%のセルが反復間で結果を変える}ことを記録し、単一サンプルのリーダーボードが
信頼できないこと、統計的処理が必要であることを論じる。
\end{abstract}

\section{はじめに}
公開LLMレッドチーミングのツール（例：garak~\cite{garak}）やジェイルブレイクのベンチマーク（例：
HarmBench~\cite{harmbench}, JailbreakBench~\cite{jbb}）は英語が主流である。多言語安全性の研究は、プロンプトを
低資源言語へ\emph{翻訳}することで安全機構を回避できることを示してきたが、言語固有の
文字・組版・敬体を悪用する\textbf{言語特有の難読化}は相対的に未開拓である。とりわけ
日本語は、複数の文字体系、全角/ゼロ幅文字、縦書き、高度に慣習化された敬語など、豊かな
難読化の表面を持つ。

さらに2つのギャップが J-ART の動機である。第一に\textbf{素のモデル評価とデプロイ
システム評価}の差：実務では、モデルに加えてシステムプロンプト、さらにガードレール、
しばしば検索が組み合わさる。セキュリティ上意味のある単位は\textbf{アプリケーション構成}で
あり、モデル単体ではない。第二に\textbf{セキュリティとコストの同時評価}：防御はトークンや
レイテンシのコストを伴うため、コスト効率スコアを併記し「最も安価で十分に安全な構成」を
直接読み取れるようにする。

本稿の貢献は次の通り：(a) 日本語難読化変形の一式、(b) 安全なプロキシマーカー方式を備えた
アプリ層・MITRE ATLAS準拠の評価ハーネス、(c) 正規化フィルタとモデルベース分類器を含む
ガードレール比較、(d) 統計的に報告するリーダーボード（Wilson信頼区間・任意のN回試行）と
コスト効率指標、(e) モデルルーター（モデル要求を実際のバックエンドに振り分ける中継層）起因の
大きな実行間ばらつきの実証的観察。

\section{関連研究}
J-ART は次の6系統の研究の交点に位置する。各系統を要約し、表~\ref{tab:related}に
位置づけをまとめる。

\paragraph{敵対的レッドチーミングのツール.} garak~\cite{garak} は\emph{モデル}
単体を既知の脆弱性プローブ集合で走査する。J-ART は、配備された\emph{アプリケーション
構成}（モデル $\times$ システムプロンプト $\times$ ガードレール $\times$ RAG）を評価単位とする。

\paragraph{ジェイルブレイク・有害行動ベンチマーク.} AdvBench/GCG~\cite{gcg}、
Jailbroken~\cite{jailbroken}、HarmBench~\cite{harmbench}、JailbreakBench~\cite{jbb}、
実環境収集プロンプト~\cite{dan} は、\emph{どの}有害行動を\emph{どう}採点するかを標準化
するが、その大半は英語・モデル層が対象である。J-ART はハーネスの発想を継承しつつ、有害
誘発を安全なプロキシマーカー目標（\S\ref{sec:markers-ja}）に置き換え、スイートを公開可能にする。

\paragraph{自動攻撃生成.} PAIR~\cite{pair} と TAP~\cite{tap} は攻撃プロンプトを反復
最適化する。J-ART は再現性と安全な開示のため、\emph{固定・監査可能}な変形一式を用いる。

\paragraph{多言語・低資源の安全性.} Deng ら~\cite{deng}・Yong ら~\cite{lowres} は低資源
言語への\emph{翻訳}でアライメントが劣化することを、Wang ら~\cite{alllang} は言語横断の
安全性般化を示す。これらは言語\emph{間}の翻訳を扱うが、J-ART は日本語固有の\emph{言語内
字形難読化}（ギャル文字・縦書き・敬語フレーミング・かな/漢字符号化）を扱う。これは日本語が
高資源であっても残存する。

\paragraph{符号化・字形難読化.} 符号化ベースの脱獄は確立した先行研究である：
CipherChat~\cite{cipherchat}（暗号会話）と ArtPrompt~\cite{artprompt}（アスキーアート字形）。
本作の \code{base64\_wrap}・\code{leet\_smuggle} はこの系統の\textbf{言語非依存な複製}であり
ベースライン用途にすぎない。新規性は日本語字形の変形（\S\ref{sec:transforms-ja}）にある。

\paragraph{プロンプトインジェクションとアプリ層評価.} Perez \& Ribeiro~\cite{perez} は目標
乗っ取り・プロンプト漏洩を、Greshake ら~\cite{greshake} は\emph{間接}注入を定式化し、Liu
ら~\cite{liu} は LLM 統合アプリのベンチマークを、AgentDojo~\cite{agentdojo} は最も近いアプリ
層評価（ツール利用エージェント）を与える。J-ART は\emph{アプリ構成}（プロンプト $\times$
ガード $\times$ RAG）を明示的な評価単位として日本語難読化面に対して評価する点で異なる。

\paragraph{ガードレール・入力分類器.} Llama Guard~\cite{llamaguard}、NeMo
Guardrails~\cite{nemo}、OpenAI Moderation API~\cite{moderation} はモデル/規則ベースの
フィルタを提供する。J-ART はガードレールを\emph{差し替え可能な構成変数}として扱い、各々の
限界防御を測る。素朴なキーワード検閲が取りこぼす難読化を破る決定論的正規化フィルタも含む
（\S\ref{sec:results-ja}）。

\paragraph{LLM-as-judge の妥当性.} Zheng ら~\cite{mtbench} と Gu ら~\cite{judgesurvey} は
LLM ジャッジの偏りを記録する。J-ART は\emph{主要}指標で LLM ジャッジを避け、決定論的な
カナリア/マーカー照合（\S\ref{sec:markers-ja}）を用いてジャッジ分散を指標から排除する。

\paragraph{日本語 NLP 資源とタクソノミ.} JGLUE~\cite{jglue} のような一般日本語ベンチマーク
は自然言語理解を対象とするが、日本語固有の難読化を狙う公開・再現可能な\emph{敵対的安全性}
ベンチマークは管見の限り存在しない。これが J-ART の埋める空白である。攻撃は MITRE
ATLAS~\cite{atlas} に対応づけ、OWASP Top~10 for LLM Applications~\cite{owasp} を相互参照する。

\section{手法}

\paragraph{アプリケーション構造層.}\label{sec:applayer-ja}
評価対象（\textbf{target}）は構成である：provider/model $\times$ prompt\_strength
$\in \{\text{naked (low)}, \text{hardened (high)}\}$ $\times$ guardrail
$\in \{\text{none}, \text{keyword}, \text{regex}, \text{llm}, \text{llamaguard}\}$
$\times$ rag $\in \{\text{true}, \text{false}\}$。簡易RAG文脈（良性の社内文書、間接
インジェクション攻撃では汚染）と、秘密の\emph{カナリア}を含むシステムプロンプトを試行ごとに
組み立てる。

\paragraph{日本語難読化変形.}\label{sec:transforms-ja}
各ベース攻撃は7種の変形のいずれかでレンダリングされる：\code{baseline}（無変形）、
\code{polite\_business}（敬語による権威付け）、\code{vertical\_newline}（1文字1行の縦書き）、
\code{gyaru}（ギャル文字の字形置換＋ゼロ幅スペース）、\code{double\_tongue}（偽の
サンドボックス/認可の前提）、\code{base64\_wrap}（Base64エンコードした指示）、
\code{leet\_smuggle}（leet記号置換＋ゼロ幅スペース）。変形は人間可読性を保ちつつ、部分文字列
一致のフィルタを破壊するよう設計される。

変形は2クラスに区別する（表~\ref{tab:transforms}）。\emph{日本語固有}の変形は日本語の
表記体系や待遇表現を悪用し、英語などに直接の対応物を持たない：\code{gyaru}（仮名字形置換）、
\code{vertical\_newline}（縦書き）、\code{polite\_business}/\code{double\_tongue}（敬語に
よる権威付けと内集団フレーミング）。\emph{言語非依存}の変形 ——
\code{base64\_wrap}・\code{leet\_smuggle}（および対照の \code{baseline}）—— は\textbf{新規
ではなく}、符号化/字形脱獄の系統（CipherChat~\cite{cipherchat}・ArtPrompt~\cite{artprompt}）の
複製であり、日本語固有面の限界効果を切り分けるための比較基準としてのみ含める。
各変形を無害な例文に適用した実出力を図~\ref{fig:transform-examples}に示す。

\paragraph{攻撃スイートと MITRE ATLAS 対応.}
11の攻撃が、推論（運用）時に行われる ATLAS 技術9種を網羅する：直接/間接プロンプト
インジェクション (AML.T0051.000/.001)、LLMジェイルブレイク (AML.T0054)、LLMデータ漏洩
(AML.T0057)、LLMプロンプト自己複製 (AML.T0061)、信頼出力/引用の操作 (AML.T0067.000)、
LLMプロンプト難読化 (AML.T0068)、システムプロンプト探索 (AML.T0069.002)、RAG汚染
（偽RAGエントリ注入を含む）(AML.T0070)。ベクトルは \code{user}（直接）または \code{rag}（間接）。

\paragraph{無害なプロキシマーカーと設計による安全性.}\label{sec:markers-ja}
危険なコンテンツの生成を避けるため、攻撃は\textbf{無害なプロキシ}を標的とする：システム
プロンプトに埋め込んだ架空のカナリア合言葉（データ漏洩攻撃）と、無害な文字列マーカー
\code{[JART-PWNED]} / \code{[JART-HIJACKED]}（注入/制御奪取攻撃）。各攻撃の悪意ある
\textbf{コア}はコード内に定義し、設定ファイルには残さず、\code{results.json} と公開サイトでは
\textbf{マスク}（伏字プレースホルダへ置換）する。表示されるのは難読化の\emph{フレームワーク}
のみであり、利用可能なレシピを与えずに構造を学べる。描画時にもクライアント側の多重マスクを
施す。

\paragraph{決定論的ジャッジ.}
突破はカナリア/マーカーの membership で判定する——完全一致\emph{および}軽い正規化後の一致。
本ジャッジは\emph{lexical}（字句的）な漏洩を検出するが、意味的/言い換えの漏洩は検出できない。
よって本指標を\textbf{lexical-leak 防御率}と呼ぶ：本稿の全防御率は真の安全性の\textbf{上限}
であり、保証ではない。人手検証付きジャッジは今後の課題。

\paragraph{ガードレール.}
5設定を比較する：\textbf{none}；\textbf{keyword}（禁止部分文字列一致——高速だが難読化に
弱い）；\textbf{regex}（\emph{正規化}フィルタ。ゼロ幅文字除去・leet逆変換・空白畳み込み・
長トークンのBase64復号を行ってから禁止語照合——決定論的でAPI追加コスト0）；\textbf{llm}
（対象モデル自身が入力を検閲し出力も審査）；\textbf{llamaguard}（専用の安全性分類モデル
——ルーター経由の Llama Guard~4——が入力を攻撃/良性に分類し、失敗時は安全側にフォール
バック）。

\paragraph{統計的処理.}\label{sec:stats-ja}
各防御率は試行数に基づく \textbf{Wilson 95\% 信頼区間}と共に報告する。各セルは $K$ 回反復
する（\code{JART\_TRIALS}。本稿ではライブ campaign が $K{=}5$、アブレーションが $K{=}3$）。
ただし試行レベルの Wilson 区間はセルの $K$ 反復を独立と扱うが、
実際は\textbf{独立でない}。したがって構成間の\emph{差}（アブレーション、\S\ref{sec:results-ja}）
には、セルごと復元抽出する\textbf{クラスタ頑健ブートストラップ95\% CI}（\code{bootstrap\_diff\_ci}、
3{,}000 再標本、固定シード）を報告する。これは試行レベルの Newcombe 区間より広く、全有意性
主張の根拠となる区間である。

\paragraph{コスト効率指標.}
$\mathrm{cospa} = \text{防御率}(\%) \div \text{100万トークンあたりコスト (USD)}$ を
報告する（単価は下限\$0.01でクランプ。すなわち\$0.01未満の単価は\$0.01として扱う）。cospa は意図的に単純な\emph{スクリーニング比}であり
効用モデルではない：単位は独立に意味を持たず、順位はクランプと価格スナップショットに感度を持つ。
よって並べ替えキーとしてのみ用い、\textbf{防御 対 コストのトレードオフ}を直接提示する。クランプ
の影響は \$0.01/100万トークン未満の構成に限られ、評価対象のモデル群には該当がない。

\paragraph{実行.}
試行は独立であり、同時実行数を制限した並列実行（既定8ワーカーのスレッドプール）で、リクエスト毎のタイムアウトと
指数バックオフ再試行のもとに実行する。シミュレーションの決定論は実行順に依存しない。APIキーが
無い対象は決定論的シミュレーションにフォールバックし、鍵が一部欠けても実行全体が落ちない。

\section{結果}\label{sec:results-ja}
完全ラベル付きの\textbf{LIVEキャンペーン}（21構成 $\times$ 11攻撃 $\times$ 7変形 $\times$
\textbf{$K=5$} 反復 $=8{,}085$ 試行、2026-06-14 実行）を報告する。各セルは \code{mode=LIVE}
と価格スナップショットでラベル付けし、\code{api\_error} の試行のみ（試行単位で）除外する——
parity 再実行後は 169/8{,}085 を除外し \textbf{$7{,}916$ クリーン試行}が残る。クリーンセルの
実課金（キャンペーン＋parity 再実行、高価な Opus を含む）は\textbf{$\approx\$6.0$}。\textbf{Opus
素は完全測定}（$n{=}385$、Anthropic 補充で parity 達成）；\textbf{Gemini-pro のみ部分的}
（$n{=}227$、分間レート制限）で\emph{暫定}扱い。全防御率は\textbf{lexical-leak の上限}
（\S\ref{sec:markers-ja}）であり、差にはすべて\textbf{クラスタ頑健CI}を付す（\S\ref{sec:stats-ja}）。
\S4の各数値は commit 済みアーティファクトから再現可能（\S\ref{sec:repro}）。

\paragraph{全体.}
全構成は \S\ref{sec:applayer-ja} の簡易RAGコンテキストを含む。\textbf{「素」は強化プロンプト
なし・ガードなしの意であり「RAGなし」ではない}（よって間接注入攻撃は素のベースラインでも対象）。
クリーン試行の総突破率は\textbf{14.5\%}（$1{,}151/7{,}916$）で、\textbf{弱構成}に集中した。
（\code{gemini-pro} はこのプールに\emph{暫定}の防御試行 $n{=}227$ を寄与する（\S\ref{sec:limits}）。
除外すると総突破率は 15.0\% となるが、全体像は変わらない。）
強化済み/ガード付き構成は\emph{どのモデルでも}\textbf{91--100\%}帯で防御したのに対し、素の
モデルは\textbf{29.6\%〜86.5\%}に散らばった（表\ref{tab:naked}）。

\paragraph{アプリ層の防御 対 モデル能力.}
構成効果をモデル能力から切り分けるため、能力域をまたぐ\textbf{3モデル}（弱い Llama-4-Scout・
安価な GPT-4o-mini・フラグシップ GPT-4.1）で均衡アブレーションを行う。各々モデルを固定し
\{素, 強化プロンプト\}~$\times$ ガードレールを直積、各構成の素ベースラインとの差を\textbf{クラスタ
頑健ブートストラップ95\% CI}（3{,}000 セル再標本。試行ではなくセルを再標本化するため、
アブレーションの $K{=}3$ 反復のセル内相関で有意性が水増しされない。\code{experiments/analyze\_ablation.py}
で再現）で報告する（表\ref{tab:ablation}）。アブレーションした3モデルすべてで2つの傾向が成り立つ：(1) \textbf{強化プロンプト}と
\textbf{モデルベースのガード}（Llama Guard・LLM自己検閲）は\emph{各モデル}で有意に防御を
上げる；(2) 効果は\textbf{素のベースラインに反比例}——弱い Scout（素38\%）では各ガードが
$+26$〜$+60$ ポイント、GPT-4o-mini（素82\%、天井近い）では軽量な keyword/regex はクラスタ
補正で\emph{有意でない}。ただし防御率は100\%で頭打ちのため、この反比例の一部は\textbf{天井
（headroom）の作用}であってガードレール固有の性質ではなく、また強化プロンプトを入れると、
その上にガードレールを重ねた追加効果はほとんどない（強化アームは100\%近くで飽和）。

したがって核心は「どれか一つの防御がモデル性能を\emph{凌駕}する」ことではなく、
\textbf{構成が素の大きなばらつきを潰す}ことである：素のモデルは29.6〜86.5\%（表\ref{tab:naked}）
だが、アブレーションした3モデルすべてで強化/ガード付き構成は\textbf{91〜100\%}帯に収まり、
\textbf{一度構成すればモデル選択の差は素のときよりはるかに小さくなる}。具体的には、強化した
安価モデル（GPT-4o-mini 強化 $\approx100\%$）が\emph{素の}フラグシップ（GPT-4.1 素 64.1\%、
$n{=}231$）を ${\sim}36$ ポイント、素の Opus（86.5\%、$n{=}385$）も上回る。この比較には2つの
限定がある。第一に、「素」は\textbf{ゼロ防御の下限}（システムプロンプトもガードレールも無い＝
誰もデプロイしない構成）であり、ギャップは\emph{構成あり vs なし}と読むべきで、モデル同士の
対等比較ではない。デプロイ現実的な最小プロンプトの baseline は今後の課題。第二に、本結果は
アブレーションした3モデル・$K{=}3$ で確立したものであり、全 fleet に対して主張するものではない。
さらに\textbf{構成妥当性}の留保が全体にかかる：判定器はカナリア/マーカーの完全一致
（第\ref{sec:markers-ja}節）なので、強化プロンプトが「マーカーを出すな」と命じると、真の拒否
ではなく\textbf{マーカー文字列の抑制}で測定値が上がりうる。よって本指標は真の強化とマーカー
抑制を完全には区別できず、defended セルの semantic-judge 監査（第\ref{sec:limits}節）が必要
である。本稿ではこれを限界として明示するに留める。

\paragraph{実行内ばらつき（主要な結果）.}
単一キャンペーン内で、構成を固定したまま各セルを\textbf{$K=5$}反復した。\textbf{全5試行が
クリーンな1{,}577セル}のうち\textbf{9.6\%（$152/1{,}577$）が5回の同一反復で結果を変えた}
——素の弱モデルに集中。当初の戒めの例「Llama~4
Scout / 素のAPI」では77セル中\textbf{32（42\%）が不安定}：14が無突破（0/5）、31が常時突破
（5/5）、32が中間。\emph{単一サンプル}のリーダーボードはこの同一構成に運次第で0\%〜100\%を
割り当てる——構成集合の交絡を排した\textbf{単一サンプルは再現しない}ことの統制された証拠で
ある。この知見は\emph{単一キャンペーン内}のばらつき（同一実行中のプロバイダ非決定性に由来）に
限定する。日をまたいだ変動（経時ドリフト）は、計測の枠組み（\code{across\_runs}）だけ用意し、
本格的な分析は今後の課題とする。

\paragraph{ガードレール比較とコスト.}
3つのモデル（表\ref{tab:ablation}）で、防御を上げる効果の順序は一貫していた。効果が最も大きい
のは\textbf{LLMガードレールと強化プロンプト}、次が\textbf{Llama Guard}、軽量な keyword/regex
フィルタは\textbf{ベースモデルが弱いほどよく効く}。入力を遮断するガードレールは、本体モデルの
呼び出し自体を省けるため、\textbf{防御を上げつつ正味コストはむしろ下がり得る}。例えば\textbf{正規化
regexフィルタ}（ユニットテストで検証済み）は、弱い Scout に対し\textbf{API追加コスト0で
$+45$ポイント}の防御を加える。コスト効率（cospa）で見ると、上位は\textbf{安価なOSSモデル＋軽量
ガード}（gpt-oss-20b~+~keyword、$\mathrm{cospa}\approx1131$）、最下位は\textbf{素のフラグシップ}
（Opus 素、$\mathrm{cospa}\approx6.8$）で、両者には\textbf{3桁（約1000倍）の開き}がある。

\paragraph{攻撃・変形の有効性.}
最も突破率が高かった攻撃は、信頼出力/引用の操作・偽RAGエントリ注入・システムプロンプト探索
だった。難読化変形どうしを比べると、意外にも\emph{無変形}の \code{baseline} が最も突破率が高く
（\textbf{22.0\%}）、次いで \code{vertical\_newline}（20.0\%）、\code{polite\_business}（17.3\%）
と続いた。一方、\textbf{\code{base64\_wrap} は最も弱かった（5.5\%）}。これは、Base64 のような重い
符号化をかけると、モデルは指示をすり抜けさせるより\textbf{むしろ拒否したり解釈に失敗したりする}
ことが多いためである。つまり\textbf{最も危険な日本語変形は、人間が読めてしまう「自然な」もの
（縦書き・敬語フレーミング）であって、暗号めいた難読化ではない}。

\section{倫理と責任ある開示}

\paragraph{設計による安全性.}
J-ART は設計により安全である。(1) 攻撃は\textbf{架空のカナリア}と\textbf{無害なマーカー}を
標的とし、実際の有害能力を扱わない。コード・データ・公開サイトのいずれにも危険物は存在しない。
(2) 悪意ある\textbf{コア}は全成果物でマスクされ、難読化のフレームワークのみが示される。
(3) モデルは研究比較のためにのみ参照され、結果は実行時スナップショットであって認証ではない。
意図する用途は、開発者が\emph{自身の}デプロイを堅牢化する支援である。

\paragraph{再利用可能な開示パターン.}
上記の設計を、運用可能な攻撃を公開せずに敵対的安全性ベンチマークを公開するための
転用可能なパターンとして一般化する：
(i)~\emph{無害なプロキシ目標}（架空カナリアと無害マーカー）により突破を測定可能だが
不活性にする；
(ii)~\emph{コア/フレームワーク分離とマスキング}——研究信号を担う難読化フレームワークは
公開し、運用コアは全成果物でマスクし、無害コアはコード内のみに保持する；
(iii)~\emph{決定論的オフラインモード}によりリポジトリ単体で結果を再現でき、稼働する
攻撃コーパスを配布しない；
(iv)~\emph{マスキングの監査}——コア（生・難読化いずれも）が公開成果物に到達しないことを
ユニットテスト不変条件で検査する。これにより手法と集計結果は完全公開しつつ、攻撃
ペイロードは秘匿される。言語固有のレッドチームデータセット全般に推奨する姿勢である。

\paragraph{ガバナンス・クロスウォーク.}
表~\ref{tab:gov}は、評価する各能力を MITRE ATLAS~\cite{atlas}、OWASP Top~10 for LLM
Applications~\cite{owasp}、NIST AI RMF~\cite{nistrmf} とその生成AIプロファイル~\cite{nistgenai}、
EU AI Act~\cite{euaiact}、日本の AI ガバナンス指針~\cite{meti,aisi} に相互参照する。本対応は\textbf{情報提供で
あり適合性の主張ではない}。適用可否は各デプロイのリスク分類に依存する。運用上 J-ART は
NIST AI RMF の\textbf{MEASURE}段階の活動であり、その出力は組織の\textbf{MANAGE}判断に
資する。

\section{限界}
\label{sec:limits}
\begin{itemize}[leftmargin=1.4em,itemsep=2pt]
  \item \textbf{プロキシマーカーであって実害ではない：}実害ではなく指示違反/漏洩の代理を測る。
  \item \textbf{決定論ジャッジ：}カナリア/マーカーを完全一致\emph{および}軽い正規化
        （大小文字畳み込み・空白/ゼロ幅除去）後に照合するため、整形してエコーされた漏洩も
        突破として計上する。一方で\emph{意味的}/言い換えによる漏洩は検出できないため、
        報告する防御率は\textbf{上限}である。人手検証付き LLM ジャッジは今後の課題。
  \item \textbf{単発（1ターン）：}多ターン/crescendo攻撃は未モデル化。
  \item \textbf{標本数：}手作りのスイート（11攻撃 $\times$ 7変形）、既定はセル当たり $N{=}1$。
  \item \textbf{プロバイダの非決定性/ルーターのばらつき：}結果はスナップショットであり、実行時の
        ルーティングとモデル版に依存する。
  \item \textbf{欠損データの偏り（概ね解消）：}以前のキャンペーンでは、一部の構成のデータが
        \textbf{偏って欠けていた}ことを指摘していた。原因は、API のレート制限が\textbf{難しい攻撃ほど
        起きやすく}、Opus の最難関の攻撃が十分に測れていなかったこと——失敗しやすい攻撃が抜け落ち、
        防御率が実際より高く見える\textbf{生存バイアス}である。\textbf{全件を測り直す parity 再実行で
        これを直接確認した}：Opus の素モデルは完全測定（$n{=}385$）で防御\textbf{86.5\%}だったのに対し、
        偏った初期スナップショット（$n{=}125$）では\textbf{89.6\%}と、予測どおり\textbf{約3ポイント
        過大評価}されていた（偏ったスナップショットは成果物として残さず、確定値 $n{=}385$ のみを
        commit）。現在 Qwen3-max と Opus は完全測定に到達。\textbf{Gemini-pro だけが部分測定}
        （$n{=}227$。分あたりのレート制限が原因で、課金を足しても解消しない）のため\textbf{暫定扱い}と
        し、主要な結論はこれに依拠しない。
  \item \textbf{コスト帰属：}ガードレールのトークンは\emph{ガードモデル自身}の単価で計上
        するよう修正（\code{llamaguard} は分類器 \code{JART\_GUARD\_MODEL}、\code{llm} は
        実際に呼び出す本体モデル）し、本体トークンと別建てで報告する。残る近似：MOCK時の
        トークン\emph{数}は推定値である。
  \item \textbf{シミュレーションモード}は鍵欠如時の決定論的代替であり、実測のモデル挙動と
        読むべきではない。
\end{itemize}

\section{再現性}\label{sec:repro}
コード・設定・デプロイ用ワークフローは公開している。ハーネスはシミュレーションモードでは決定論的
であり、LIVE結果は実行時のプロバイダ・ルーティングとモデル版に依存するため、実行日とモデル識別子
と共に報告すべきである。使用した正確なモデル識別子と単価はリポジトリを参照のこと。
各セルは来歴ラベル——\code{mode}（\code{LIVE}/\code{MOCK}）、\code{api\_error}、解決済み
モデル、\code{price\_per\_million} スナップショット——を持ち、シミュレーションセルはLIVE集計
から除外される。\textbf{\S\ref{sec:results-ja}の全数値は commit 済みアーティファクトから再現
可能}：\code{experiments/var\_run.json}（\S4.1全体・素のスプレッド・分散・変形・cospa）と、
3つのアブレーションファイル \code{ablation\_results.json}（GPT-4o-mini）・
\code{abl\_scout\_results.json}（Llama-4-Scout）・\code{abl\_gpt41\_results.json}（GPT-4.1、
表\ref{tab:ablation}）。集計とクラスタ頑健CIは \code{analyze\_ablation.py} /
\code{analyze\_variance.py} で再計算する。\textbf{公開リーダーボードは commit 済みの LIVE
キャンペーン成果物}（\code{var\_run.json}）を配信するため、本稿の数値とサイトが一致する。
新規 LIVE 再測定は定期実行（および手動）で行い、push 時は課金せず commit 済み成果物を再公開
するため、サイトが MOCK と LIVE を混在させることはない。

\section*{AIによる支援の開示}
著者は本研究全体にわたり、Claude Code コマンドラインインターフェース経由で
\textbf{Claude Opus~4（Anthropic）}を補助として用いた。その用途は二つである。
\textbf{(A) 執筆：}査読対応の3ラウンドにわたる本文の草稿作成と改訂、日本語アブストラクト
および英語版（\code{technical-report.tex}）との二言語編集、引用エラーの点検（著者帰属・

手法に関する決定——実験設計、用いる統計手法とその根拠（例：セル内の相関を考慮し、試行

としての役割と研究対象としての役割は別個であり、透明性のため双方をここに開示する。本稿の
